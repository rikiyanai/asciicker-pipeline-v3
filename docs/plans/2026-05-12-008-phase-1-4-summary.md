## Executive Summary

The RenderPlanTable replacement architecture has been implemented across Phases 1-3. This architecture eliminates runtime guesswork by replacing the old selector-driven bundle system with an explicit compile-time approach:

**Old (Deleted):**
```
XP → bundle → selector → resolver → fallback chain → compose
```

**New (Current):**
```
ActorVisualProfile → ServerVisualKey → RenderPlan row → dumb presenter
```

**Key Achievements:**
- ✅ No runtime inference (variation is explicit)
- ✅ No fallback search (exact lookup)
- ✅ No special cases (crossbow is variation, mounted is domain)
- ✅ No Python-only green (C++ parser gate mandatory)
- ✅ No hash-only green (full parse validation)
- ✅ No build-web-only green (E2E smoke test)

## Key Decisions

### 1. Variation is Explicit

**Old:** Inferred from runtime state masks
**New:** Dropdown selection in workbench

**Impact:** No runtime inference logic needed

### 2. Mount is a Domain

**Old:** Special runtime composer
**New:** Domain choice with mount_composition

**Impact:** No special-case runtime paths

### 3. Crossbow is a Variation

**Old:** Special runtime logic
**New:** Variation dimension string

**Impact:** No crossbow special case in runtime

### 4. Layers are Ordered

**Old:** Fallback search for missing layers
**New:** Array order = render order

**Impact:** No fallback search logic needed

### 5. C++ Parser Gate is Mandatory

**Old:** Python-only validation
**New:** C++ parser gate in build-web.sh

**Impact:** No Python-only green, no hash-only green

### 6. Key Space Coverage Tracking

**Old:** No tracking
**New:** total_keys/covered_keys/missing_keys

**Impact:** Visibility into coverage gaps
